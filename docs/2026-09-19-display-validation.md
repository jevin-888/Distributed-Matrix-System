# 2026-09-19 显示修复及未完成项

## HDMI 启动动画

现象：进度条播放时，HDMI 大屏顶部有一条花屏。输出为 1280×720@60，动画文件为
1920×1080@30，板上文件哈希与项目一致。原程序在 Smart0-win1（78）播放动画，
同时保留同组 Smart0-win0（56）的开机底图；该驱动的多区域窗口共享父窗口叠加设置。
冷启动日志在动画阶段出现 VOP2 POST_BUF_EMPTY。

修正：动画直接使用配置的背景主图层，保持当前显示模式；播放前释放旧背景管线。
第一版用户确认顶部花条消失，冷启动日志无 POST_BUF_EMPTY，但动画结束黑屏一下。
进一步保留动画 EOS 后的最后一帧和管线，背景图完成启动后再释放旧管线，用户确认
“不会黑了”。实际启动日志显示末帧保留后约 1.14 秒背景图上屏，主图层正常显示背景图。

CTest 9/9 及 ARM 编译通过。最终现场应用 SHA256：
`98b7884ec6bcb3cb4c3ba083bc841572c9a4d38f30fd41bf37c7ff9a29e66619`。
U-Boot、内核和 OLED 初始化在本轮均未修改。API 未变。

## OLED 上电瞬间闪花：未解决

用户观察：通电瞬间闪花 → 黑屏 → 正常显示第二行居中的 system login → 设备信息。
曾有一轮反馈两屏正常，但随后再次复发，不能据单次正常判定稳定。

实机冷启动已确认 v21 U-Boot 执行 `arch_cpu_init` 的 GPIO14 复位保护，读回为低。
GPIO14 是已实物验证的 I2C_TP RST；GPIO13 拉低不能熄屏，未将其作为供电使能使用。
ROM 仍使用原厂 DDR/SPL，物理通电到 U-Boot 进入前不在当前软件保护范围内。

下一步需要确认的信号是小屏 RES#（J2 第 5 脚，经 R4 至屏 J1 第 8 脚）相对
VDD_3V3 的上电波形，以及 VBAT/VCC 上电过程。当前只有串口日志与用户观察，
无法证明闪花的准确电气起因；增加 Linux 延时不能覆盖通电初始窗口。

硬件修正的目标应是：电源爬升和主板 GPIO 尚未接管时，屏侧 RES# 已被可靠保持为低；
电源稳定且主板明确释放后才解除复位。按现有图纸，屏侧复位仅由主板直接接入，
没有看到独立上电复位监督电路，但实际装配及主板侧默认状态还需硬件人员核对。
可由硬件人员评估复位监督/隔离电路与默认下拉的组合，确保不会与主板推挽输出冲突。
在未确认主板默认上下拉、电源域和复位时序前，不给出直接短接、任意加电容或固定
电阻值的操作方案，也不把替换厂商加载器作为未经验证的现场处理。

验收条件：按可复现条件断电并放电后多轮启动，OLED 从通电至设备信息全程无花屏；
HDMI 进度动画无顶部花条、结束到背景图无黑屏。当前仅 HDMI 两项通过用户实测，
OLED 通电全程无花屏仍未通过。
